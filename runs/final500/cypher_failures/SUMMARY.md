# Graph query failures in the latest run (final500)

Agentic Hybrid RAG asks the graph through `cypher_search`: a second GPT-6 Luna call
writes one read-only Cypher query, and code runs it on Neo4j (10 s limit, at most 10
rows). This counts how often that query failed or came back empty, over every
Agentic Hybrid RAG answer in the latest run: 3 datasets × 500 questions × 3 repeats.
Generated by `compute.py` (run from the repo root); numbers in `cypher_failures.json`.

| Dataset | Graph queries | Failed | Ran, found nothing | Answers with a failed query |
|---|---|---|---|---|
| MultiHop-RAG | 1,538 | 85 (5.5%) | 563 (36.6%) | 84 of 1,500 |
| HotpotQA | 1,522 | 142 (9.3%) | 405 (26.6%) | 137 of 1,500 |
| Natural Questions | 1,509 | 110 (7.3%) | 153 (10.1%) | 107 of 1,500 |
| All three | 4,569 | 337 (7.4%) | 1,121 (24.5%) | 328 of 4,500 |

About 1 graph query in 13 failed, and about 1 in 3 (1,458 of 4,569) gave the agent
nothing, failed or empty.

## Why they failed

Almost all failures are bad queries written by the model, not database problems:

- **171, not valid Cypher.** Often a name with an apostrophe closed the quoted string
  early (`'s blockade of gaza'`), or the model wrote `CASE ... THEN` in the wrong place.
- **150, valid Cypher asking for something impossible.** The largest group, 104, called
  `toLower` on a field that holds a list rather than text. Others parsed text that is not a
  date as a date (13), mixed up node and relationship types (10), or returned two columns
  with the same name (7).
- **13, hit the 10-second limit.**
- **3, ran out of database memory.**

No query was refused for asking for article text, and none tried to write.

## What a failure does to the answer

Nothing breaks: the agent reads the error message and can search again or stop. Not yet
measured: whether the 328 answers with a failed query were more often wrong.

## Where a change would go, if wanted

The text-to-Cypher prompt is `CYPHER_PROMPT` in `graphrag_retrieval.py`. Two cheap
changes would remove most failures: pass names as query parameters instead of quoted
strings (the apostrophe cases), and tell the model which properties are lists (the
`toLower` cases). Neither has been tried.
